# Genera (generazione singola e massiva) — Piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una scheda "Genera" che produce PDF (e, a scelta, HTML) da template key, elenco CSV o FDI, verso svil/coll, con header modificabili, cartelle per package name, zip ed esiti per riga.

**Architecture:** Un motore senza Qt in `src/qtrequestory/officina/batch/` (elenco, header, risoluzione, esecuzione a 3 thread, scrittura) esposto da un `BatchMixin` su `OfficinaService` e dal Protocol `OfficinaApi`. La scheda lo lancia come **un solo** job esclusivo del `JobRunner` e si aggiorna dagli eventi. Si riusano `generator.send`/`sniff`, `delivery.safe_component`, `IndexService.search`/`read_body`, `HeaderTable`.

**Tech Stack:** Python (stdlib nel motore), PySide6 Widgets, pytest + pytest-qt (offscreen).

**Spec:** `docs/superpowers/specs/2026-11-10-genera-design.md`

**Orchestrazione:** ramo `genera` da `main`; un commit per task, nessun push. Modello ed effort sono indicati in ogni task. T1 → T2 → T3 → T4 → T5 in sequenza (ognuno consuma le interfacce del precedente); T6 in parallelo a T5 dove indicato; T7 alla fine.

## Global Constraints

- `core` solo stdlib; `officina` mai Qt; solo `ui` importa PySide6; `cli.py` non importa `officina`. La UI passa dai Protocol di `ui/contracts.py`.
- Mai PROD: ogni invio passa da `generator.send` (che applica `generator_url_problem`).
- Mai payload, header, corpo delle risposte o link non mascherati in log, eventi o `esito.csv`. I motivi passano da `links.mask_text`.
- Ogni componente di percorso da dati utente passa da `delivery.safe_component`.
- Stringhe utente in italiano, solo in `ui/strings/genera.py`; vietate le parole inglesi della denylist di `tests/ui/test_strings.py`. Identificatori in inglese.
- Nessun colore o stylesheet fuori da `ui/theme*.py`; ruoli via `theme.set_role`.
- `QSettings` solo via `actions.user_settings()`.
- Moduli ≲ 400 righe. Dati di test sintetici (`MOD_TEST_*`, FDI `aaaaaaaa-1111-…`), nessun hostname o percorso reale.
- Test: `.venv\Scripts\python -m pytest` dalla radice del repo; l'intera suite deve restare verde a ogni commit.
- Valori fissi: `NO_PACKAGE = "_senza_pacchetto"`, 3 thread, soglia di conferma 20 chiamate, cartella `<ambiente>_<AAAAMMGG-HHMMSS>`, `esito.csv` con `;` e UTF-8 con BOM.

## Review Focus

1. **Elenco reale sporco**: file cp1252 con package che differiscono solo per spazi finali e template key ripetute → un package solo, nessun doppione, nessun crash di decodifica. (T1)
2. **Template key scritta con maiuscole diverse o con spazi/virgole in più** → stessa chiamata trovata, nessun elemento vuoto. (T2)
3. **Destinazione non scrivibile o disco pieno a metà lotto** → la riga diventa "non riuscito" con motivo, il lotto prosegue, `esito.csv` viene comunque tentato. (T3)
4. **Interruzione a metà** → nessun file `.part` rimasto, le righe non partite sono "annullato", il report torna comunque. (T3)
5. **Due template key che differiscono solo per caratteri non validi su Windows, o stessa key due volte in un FDI** → due file distinti (`_2`), nessuna sovrascrittura. (T3)

Comportamento di `run_batch`, in ordine:
1. Generatore non abilitato/non valido, o `build_headers` di prova che solleva `HeaderError` → `ValueError` con il motivo (niente parte, niente cartella creata).
2. `resolve`; `sink(BatchStarted(total))`.
3. Per ogni `Call`, su `ThreadPoolExecutor(WORKERS)`; l'ordine di `outcomes` è quello dei `Call`:
   - `cancel.is_set()` prima dell'invio → `cancelled`.
   - `hit is None` → `no_call`, motivo `"nessuna chiamata nei log di <source_env>"`.
   - `not request.save_html and memory.is_html(key)` → `html_skipped` senza chiamare, motivo `"HTML già noto: non richiesto"`.
   - corpo non leggibile o non JSON → `failed`, motivo `"payload non leggibile"`.
   - `send(...)`; `not result.ok` → `failed` con `result.reason` e `result.status`.
   - `memory.record(key, doc_type)`; HTML con `save_html` spento → `html_skipped`, motivo `"HTML non richiesto"`.
   - `Writer.write` → `ok`; `OSError` → `failed`, motivo `mask_text(f"scrittura non riuscita: {exc}")`.
   - Qualunque altra eccezione nel lavoro di una riga → `failed` con motivo mascherato; **mai** fuori dal thread.
   - `sink(BatchItemDone(outcome, done, total))` dopo ogni riga.
4. `write_esito` sempre (anche dopo interruzione); `zip_folders` solo se `make_zip` e non interrotto. Un `OSError` qui non perde il report: `zips == ()` e il problema va nel log dell'app con `mask_text`.
5. Ritorna `BatchReport(..., cancelled=cancel.is_set())`. Non solleva `Cancelled`.

`Writer.write`: nome `safe_component(key) + "." + ext`, prima cartella scritta con `.part` + `replace_with_retry`, le altre con copia atomica dello stesso contenuto; nome già preso **in questa generazione** nella stessa cartella → `_2`, `_3`…

`write_esito`: `csv.writer(delimiter=";")`, `utf-8-sig`, intestazione `template_key;cartella;fdi;esito;tipo;file;durata_ms;stato_http;motivo`; una riga per `Outcome`; `cartella` e `file` uniti con ` | `; `file` relativo a `run_dir`; `esito` in italiano: `ok`, `saltato: HTML`, `nessuna chiamata nei log`, `non riuscito`, `annullato`.
